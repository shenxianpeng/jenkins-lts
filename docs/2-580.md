# Jenkins 2.580 LTS upgrade guide

> Covers: 2.580.1 (2026-09-30) and 2.580.2 (2026-10-28)
>
> Maintained by: Xianpeng Shen ([@shenxianpeng](https://github.com/shenxianpeng))
>
> Sources: the official [upgrade guide](https://www.jenkins.io/doc/upgrade-guide/2.580/), the [LTS changelog](https://www.jenkins.io/changelog-stable/), the [2026-10-28 security advisory](https://www.jenkins.io/security/advisory/2026-10-28/), and my own upgrade rehearsals of 38 LTS lines with [jenkins-upgrade-check](https://github.com/keelinfra/jenkins-upgrade-check).
>
> Drafted with AI from the official sources and checked against them. If you find a mistake, please open an issue.

The official upgrade guide tells you what changed in this release. This guide tries to answer a different question: **what happens when you upgrade from the version you run today.**

## In short {#in-short}

**On 2.401.3 or newer:** a normal upgrade works, but you must move to Java 21 or 25 first.

**On 2.346.3 or older:** do not just replace the war file. Upgrade in steps, see the table below.

2.580.2 fixes 15 security issues, 13 of them rated high. If you are on 2.580.1, move to 2.580.2 soon.

---

## 1. Check Java first {#java}

2.580 supports **Java 21 and Java 25** only.

| Java | Last LTS that supports it |
|---|---|
| Java 8 | 2.346.3 |
| Java 11 | 2.462.3 |
| Java 17 | **2.541.3** |

If your controller still runs on Java 17, change Java before you change Jenkins. Agents too: upgrade the Java on your agents together with the controller, or they will not connect.

Official Java guides: [Java 17 to 21](https://www.jenkins.io/doc/book/platform-information/upgrade-java-to-21/), [Java 21 to 25](https://www.jenkins.io/doc/book/platform-information/upgrade-java-to-25/).

## 2. What happens from your version (rehearsed) {#rehearsal}

**How I tested:** for each LTS line, I took its last release with the 300 most installed plugins, each at the newest version that line can load. Then I replaced only the core with 2.580.2, kept the same plugin files, started Jenkins in a container with no network, and recorded which plugins failed to load. These 38 lines cover 79.1% of the controllers that reported usage to Jenkins in March 2026.

| Your version | Replacing only the core (war or image) | Suggested path |
|---|---|---|
| 2.541.3 to 2.568.3 | ✅ all plugins load | Java 21 → 2.580.2 |
| 2.401.3 to 2.528.3 | ✅ all plugins load | from 2.479.3: straight to 2.580.2; 2.401.3 to 2.462.3: 2.541.3 (Java 17) → 2.580.2 (Java 21) |
| 2.361.4 to 2.387.3 | ⚠️ blueocean-rest-impl loads in part | 2.541.3 (Java 17) → 2.580.2 (Java 21) |
| 2.289.3, 2.303.3 | ⚠️ about 100 plugins fail (many already fail before the upgrade) | 2.462.3 (Java 11) → 2.541.3 (Java 17) → 2.580.2 (Java 21) |
| 2.164.3 to 2.346.3 (except the two above) | ❌ **Jenkins does not start** | 2.462.3 (Java 11) → 2.541.3 (Java 17) → 2.580.2 (Java 21) |
| 2.89.4 to 2.150.3 | ⚠️ more than 120 plugins fail | 2.346.3 (Java 11) → 2.541.3 (Java 17) → 2.580.2 (Java 21) |
| 2.60.3, 2.73.3 | ⚠️ 9 plugins load in part | same as above |

Following the suggested path, **every step loads all plugins** from all 38 starting points.

With only the 100 most installed plugins it looks better: Jenkins starts from every line, but all 21 lines before 2.356 still have plugins that fail.

Full data, per line and per plugin: [2.580.2 upgrade matrix](https://github.com/keelinfra/jenkins-upgrade-check/tree/matrix/2.580.2).

**Limits of this test:**
- It only checks whether plugins load at startup. A plugin that loads can still fail later, in a pipeline step or on a page.
- No real jobs, no real configuration, no network. To rehearse with your own configuration, run `jenkins-upgrade-check plan`, then `jenkins-upgrade-check dry-run --plan plan.json --home <your JENKINS_HOME>` (needs Docker).

## 3. Changes to watch {#changes}

### 3.1 Detached plugins removed from the war (affects 2.355 and older) {#detached-plugins}

These plugins, split out of core years ago, are no longer bundled in `jenkins.war` (the war is more than 20 MB smaller):

bouncycastle API, Command Agent Launcher, Oracle JDK Installer, JAXB, Trilead API, SSH server, JavaBeans Activation Framework API, JavaMail API, Instance Identity.

**Who is affected:** instances upgraded directly from **2.355 or older** that do not have these plugins installed.

**Where I disagree with the official guide:** the official guide says that if the update center is reachable, Jenkins installs these plugins automatically, so only offline instances are affected. In the 2.580.2 code, startup loads detached plugins only from the war and does not download them. The network is only used when you install a plugin through the plugin manager. So an instance upgraded directly from 2.355 or older can fail to start even with network access. The typical error is `NoClassDefFoundError` for `InstanceIdentity`, followed by `Unable to inject class` errors. (My rehearsals ran without network, so this part is based on reading the code, not on a run.)

**What to do** (pick one):
- Before upgrading, download these plugins from the update center and put them in `$JENKINS_HOME/plugins/`.
- Or upgrade in two steps: first to an LTS that still bundles them (2.568.3 or older), let Jenkins install them, then to 2.580.x.

### 3.2 Upgrading directly from 1.577 or older {#from-1577}

JUnit, Mailer, Matrix Authorization Strategy, Matrix Project and OWASP Markup Formatter are no longer bundled either. Only direct upgrades from **1.577 or older** (2014) are affected.

In that case, install these 5 plugins before starting the new version. Otherwise an instance using matrix-based security may not start, and configuration that needs these plugins cannot be loaded and may be lost the next time it is saved.

### 3.3 `Object`-typed fields are no longer deserialized by default (since 2.572) {#object-fields}

To block a class of deserialization vulnerabilities, Jenkins no longer reads XML values into fields typed as `Object`, unless the plugin marks the field as safe.

**Who is affected:** instances with third-party plugins that have such fields and are not updated yet. You will see a log message that deserialization of an `Object` field was blocked, and that configuration is not loaded.

**Temporary workarounds** (update the plugin first; use these only if you cannot):
- `-Dhudson.util.RobustReflectionConverter.SAFE_TYPES_WITH_OBJECT_FIELDS=<class1>,<class2>`: allow only the listed classes. Preferred.
- `-Dhudson.util.RobustReflectionConverter.ALLOW_ALL_OBJECT_FIELDS=true`: turn the protection off. Strongly discouraged, temporary only.

Details: [XStream and Object-typed Fields](https://www.jenkins.io/doc/developer/persistence/xstream-object-fields/)

### 3.4 Behavior changes from the 2.580.2 security fixes {#security}

2.580.2 fixes 15 issues (13 high, 2 medium), including remote code execution through XStream deserialization, an agent launch command approval bypass, arbitrary file read, several XSS issues, and a race condition in the setup wizard that allows creating an administrator account.

Some fixes make deserialization stricter. If a plugin cannot load its configuration after the upgrade, the advisory lists these switches (all temporary):

| System property | Effect |
|---|---|
| `hudson.util.XStream2.SUPPRESS_TYPE_PERMISSION=true` | turns off the new XStream type permission check |
| `hudson.util.RobustReflectionConverter.skipFieldValueElementTypeCheck=true` | turns off the collection element type check |
| `hudson.util.RobustReflectionConverter.fieldValueElementCheckLimit=<number>` | changes how many elements are checked |
| `hudson.util.RobustReflectionConverter.acceptNonIterableCollections=true` | suppresses errors for collection fields that cannot be iterated after deserialization |

Details: [Jenkins Security Advisory 2026-10-28](https://www.jenkins.io/security/advisory/2026-10-28/)

### 3.5 Other changes worth knowing {#other-changes}

- Job status icons now show only the current build's status, not mixed with the previous one.
- Sign in, registration, About, System Log, notifications and the command palette have a refreshed, consistent look.
- New password complexity rules, and an extension point for custom password validation.
- Admins can set the "Keep me signed in" validity with `hudson.security.TokenBasedRememberMeServices2.tokenValidity`, up to 1 year.
- The CLI accepts ECDSA and Ed25519 keys.
- Fixed: the Cancel button is back on the Console Output page of running builds.
- 2.580.2 updates Jetty to 12.1.14.

## 4. Checklist before you upgrade {#checklist}

1. Back up `$JENKINS_HOME` (at least `config.xml`, `jobs/`, `plugins/`, `secrets/`).
2. Make sure the controller and all agents can run Java 21 or 25.
3. Check the table in section 2 to see if you need to upgrade in steps.
4. On 2.355 or older: put the plugins from 3.1 into `plugins/` first.
5. Try it on a copy first, then on production.
6. After the upgrade, check the warnings at the top of Manage Jenkins and the system log, especially messages about `Object` fields or XStream.
