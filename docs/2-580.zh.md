# Jenkins 2.580 LTS 升级指南

> 适用版本：2.580.1（2026-09-30）、2.580.2（2026-10-28）
>
> 整理：沈显鹏（GitHub [@shenxianpeng](https://github.com/shenxianpeng)）
>
> 依据：Jenkins 官方[升级指南](https://www.jenkins.io/doc/upgrade-guide/2.580/)、[LTS 更新日志](https://www.jenkins.io/changelog-stable/)、[2026-10-28 安全公告](https://www.jenkins.io/security/advisory/2026-10-28/)，加上我用 [jenkins-upgrade-check](https://github.com/keelinfra/jenkins-upgrade-check) 对 38 个 LTS 版本做的实测。
>
> 本文由 AI 根据官方英文资料起草，我逐条核对过原文。有错误欢迎提 issue。

## 一句话 {#in-short}

**现在在 2.401.3 或更新版本上的，按正常流程升就行，但必须先把 Java 换到 21 或 25。**

**在 2.346.3 或更老版本上的，不要直接换 war 包，要分几步走，具体看下面的表。**

2.580.2 修了 15 个安全漏洞，其中 13 个是高危，还在 2.580.1 的建议尽快升到 2.580.2。

---

## 一、先检查 Java {#java}

2.580 只支持 **Java 21 和 Java 25**。

| Java | 最后一个支持它的 LTS |
|---|---|
| Java 8 | 2.346.3 |
| Java 11 | 2.462.3 |
| Java 17 | **2.541.3** |

也就是说，只要你的 controller 还跑在 Java 17 上，就得先换 Java，再换 Jenkins。agent 也一样：agent 的 Java 要和 controller 一起升，否则节点连不上。

官方的 Java 升级说明：[从 17 升到 21](https://www.jenkins.io/doc/book/platform-information/upgrade-java-to-21/)、[从 21 升到 25](https://www.jenkins.io/doc/book/platform-information/upgrade-java-to-25/)。

## 二、从你的版本升过来会怎样（实测） {#rehearsal}

**测法**：每个 LTS 版本取最后一个小版本，装上安装量最高的 300 个插件，并把这些插件都更新到这个版本能装的最新版。然后只把核心换成 2.580.2、插件不动，在不联网的容器里启动，看哪些插件加载失败。这 38 个版本覆盖了 2026 年 3 月 Jenkins 官方统计里 79.1% 上报数据的实例。

| 你现在的版本 | 只换核心（war 包或镜像）的结果 | 建议的升级路线 |
|---|---|---|
| 2.541.3 ～ 2.568.3 | ✅ 全部插件正常加载 | 换 Java 21 → 直接升 2.580.2 |
| 2.401.3 ～ 2.528.3 | ✅ 全部插件正常加载 | 2.479.3 起直接升；2.401.3 ～ 2.462.3 先升到 2.541.3（Java 17），再升 2.580.2（Java 21） |
| 2.361.4 ～ 2.387.3 | ⚠️ blueocean-rest-impl 部分加载失败 | 先升到 2.541.3（Java 17），再升 2.580.2（Java 21） |
| 2.289.3、2.303.3 | ⚠️ 约 100 个插件加载失败（升级前就有一批插件起不来） | 2.462.3（Java 11）→ 2.541.3（Java 17）→ 2.580.2（Java 21） |
| 2.164.3 ～ 2.346.3（除上面两个） | ❌ **Jenkins 起不来** | 2.462.3（Java 11）→ 2.541.3（Java 17）→ 2.580.2（Java 21） |
| 2.89.4 ～ 2.150.3 | ⚠️ 120 多个插件加载失败 | 2.346.3（Java 11）→ 2.541.3（Java 17）→ 2.580.2（Java 21） |
| 2.60.3、2.73.3 | ⚠️ 9 个插件部分加载失败 | 同上 |

按建议的路线分步升级，38 个起点**每一步都能正常加载全部插件**。

只装最常用的 100 个插件时情况好一些：没有起不来的，但 2.356 之前的 21 个版本都有插件加载失败。

完整数据（每个版本、每个插件）：[2.580.2 升级矩阵](https://github.com/keelinfra/jenkins-upgrade-check/tree/matrix/2.580.2)。

**这个实测的局限：**
- 只看启动时插件能不能加载。插件加载成功，运行到某个流水线步骤时仍可能出错。
- 没有真实的任务和配置，也没联网。想用你自己的配置预演，可以先用 `jenkins-upgrade-check plan` 生成路线，再跑 `jenkins-upgrade-check dry-run --plan plan.json --home <你的 JENKINS_HOME>`（需要 Docker）。

## 三、需要注意的变化 {#changes}

### 1. 一批拆分插件不再打包进 war（影响 2.355 及更早版本） {#detached-plugins}

从核心里拆出去的这些插件，不再随 `jenkins.war` 一起提供，war 包因此小了 20 MB 以上：

bouncycastle API、Command Agent Launcher、Oracle JDK Installer、JAXB、Trilead API、SSH server、JavaBeans Activation Framework API、JavaMail API、Instance Identity。

**谁受影响**：从 **2.355 或更早**直接升上来、并且没装这些插件的实例。

**官方指南的说法和我的判断不一样：** 官方说只要能连上更新中心，Jenkins 会自动装好这些插件，只有离线实例受影响。但我看 2.580.2 的启动代码，启动时只从 war 包里加载这些插件，不会联网下载；联网补装只发生在你通过插件管理器安装插件的时候。所以联网的实例从 2.355 或更早直接升，也可能起不来。典型报错是 `NoClassDefFoundError: ...InstanceIdentity`，接着一串 `Unable to inject class`。（我的实测没联网，所以这一条是根据代码判断的，不是跑出来的。）

**怎么做**（二选一）：
- 升级前，从更新中心下载这些插件，放进 `$JENKINS_HOME/plugins/`；
- 或者分两步：先升到还打包这些插件的版本（2.568.3 或更早的 LTS），让 Jenkins 装好它们，再升 2.580.x。

### 2. 从 1.577 或更早直接升级 {#from-1577}

JUnit、Mailer、Matrix Authorization Strategy、Matrix Project、OWASP Markup Formatter 这 5 个插件也不再打包。只有从 **1.577 或更早**（2014 年的版本）直接升级才受影响。

这种情况一定要先装好这 5 个插件再启动新版本。否则用矩阵权限的实例可能直接起不来，依赖这些插件的配置读不出来，下次保存时可能被丢掉。

### 3. 默认禁止反序列化 `Object` 类型的字段（2.572 起） {#object-fields}

为了堵住一类反序列化漏洞，Jenkins 不再把 XML 里的值读进类型是 `Object` 的字段，除非插件明确声明这个字段安全。

**谁受影响**：用了还没适配的第三方插件、而插件恰好有这种字段的。表现是日志里提示某个 `Object` 字段的反序列化被拦截，相关配置读不出来。

**临时绕过**（先升级插件，升不了再用）：
- `-Dhudson.util.RobustReflectionConverter.SAFE_TYPES_WITH_OBJECT_FIELDS=<类名1>,<类名2>`：只放行指定的类，推荐；
- `-Dhudson.util.RobustReflectionConverter.ALLOW_ALL_OBJECT_FIELDS=true`：整个关掉，官方强烈不建议，只能临时用。

说明：[XStream and Object-typed Fields](https://www.jenkins.io/doc/developer/persistence/xstream-object-fields/)

### 4. 2.580.2 的安全修复带来的行为变化 {#security}

2.580.2 修了 15 个漏洞（13 个高危、2 个中危），包括 XStream 反序列化远程代码执行、agent 启动命令审批绕过、任意文件读取、多处 XSS、安装向导里能抢先创建管理员账号等。

其中几处修复收紧了反序列化检查。万一升级后有插件因此读不出配置，官方给了这几个开关（都是临时措施）：

| 系统属性 | 作用 |
|---|---|
| `hudson.util.XStream2.SUPPRESS_TYPE_PERMISSION=true` | 关掉新加的 XStream 类型权限检查 |
| `hudson.util.RobustReflectionConverter.skipFieldValueElementTypeCheck=true` | 关掉集合元素类型检查 |
| `hudson.util.RobustReflectionConverter.fieldValueElementCheckLimit=<数字>` | 调整元素检查的数量上限 |
| `hudson.util.RobustReflectionConverter.acceptNonIterableCollections=true` | 忽略反序列化后无法遍历的集合字段报错 |

详情：[Jenkins 安全公告 2026-10-28](https://www.jenkins.io/security/advisory/2026-10-28/)

### 5. 其他值得知道的变化 {#other-changes}

- 任务状态图标改了：现在只显示当前这次构建的状态，不再混进上一次的状态。
- 登录、注册、关于页、系统日志、通知、命令面板等界面统一了样式。
- 新增密码复杂度规则，以及可以自定义密码校验的扩展点。
- 管理员可以用 `hudson.security.TokenBasedRememberMeServices2.tokenValidity` 设置"保持登录"的有效期，最长 1 年。
- CLI 支持 ECDSA 和 Ed25519 私钥。
- 修复：运行中构建的控制台页面重新有了"取消"按钮。
- 2.580.2 把 Jetty 升到 12.1.14。

## 四、升级前的检查清单 {#checklist}

1. 备份 `$JENKINS_HOME`（至少 `config.xml`、`jobs/`、`plugins/`、`secrets/`）。
2. 确认 controller 和所有 agent 都能跑 Java 21 或 25。
3. 对照第二节的表，看你需不需要分步升级。
4. 2.355 或更早的实例：先把第三节第 1 条里的插件放进 `plugins/` 目录。
5. 先在副本上试一遍，再动生产环境。
6. 升级后看一眼"管理 Jenkins"页面顶部的告警和系统日志，重点搜 `Object` 字段、`XStream` 相关的报错。
